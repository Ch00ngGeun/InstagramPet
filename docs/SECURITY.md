# 권한과 로컬 데이터

이 MVP는 개인 Mac에서 빌드해 사용하는 개발용 프로젝트입니다. Instagram 로그인은 Chrome 페이지에서 유지하고, 확장 프로그램은 페이지가 표시한 DOM에서 후보 메시지를 찾습니다. 선택적으로 펫 앱이 로컬 메시지 DB, 카카오톡 접근성 목록과 알림센터의 카카오톡 알림 기록을 읽습니다. 세 소스의 메시지는 이 Mac 안의 큐와 앱에서만 처리합니다. 서버·분석 SDK·원격 수집 서비스는 없습니다.

## 요청하는 권한

Chrome 확장 프로그램 권한의 기준은 `extension/manifest.json`입니다.

- `storage`: 발신자 허용 목록, 앱에서 받은 Instagram 설정, 별도로 보존한 수동 설정, 중복 기록 및 제한된 전달 대기 상태.
- `nativeMessaging`: 설치한 Swift 호스트와 Chrome의 표준 통신.
- `alarms`: 로컬 대기 이벤트 재전송과 앱의 Instagram 설정 재확인. Instagram 서버를 백그라운드 조회하지 않습니다.
- `content_scripts.matches`: HTTPS `instagram.com`과 `www.instagram.com`에만 삽입. 페이지 안에서 경로를 추가 검사합니다.
- `scripting` + 같은 두 주소의 `host_permissions`: 확장을 다시 로드하거나 업데이트할 때 이미 열린 Instagram 탭에 같은 content script를 다시 넣는 용도로만 씁니다. 대상 사이트는 늘어나지 않습니다.

전체 웹사이트, Chrome 쿠키, 방문 기록, 화면 녹화 권한은 필요하지 않습니다. Instagram 기능에는 macOS 손쉬운 사용·전체 디스크 접근 권한도 필요하지 않습니다. 권한과 웹사이트 범위를 최소화하는 것은 Chrome의 권장 방식입니다. [Chrome permissions](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions), [Chrome extension security](https://developer.chrome.com/docs/extensions/develop/security-privacy/stay-secure)

설정한 로컬 소스만 다음 macOS 권한을 사용합니다. 권한은 Chrome이 아닌 **설치된 InstagramPet.app**에 부여합니다.

- **Messages — 전체 디스크 접근:** `~/Library/Messages/chat.db`를 시스템 SQLite의 `mode=ro`와 `SQLITE_OPEN_READONLY`로 엽니다. 등록한 전화번호·이메일 각각의 1:1 수신 행, 본문, 읽음 상태, 첨부 MIME 종류를 조회합니다. 본인 발신·그룹·등록하지 않은 연락처는 전달하지 않고, 최초 성공한 조회는 과거 이력 재생 없이 기준 상태로 잡습니다. DB 변경 SQL·읽기/쓰기 재시도·체크포인트·원본 파일 권한 변경을 수행하지 않습니다. 첨부 파일은 열지 않습니다. 실시간 WAL 변경을 관측해야 하므로 라이브 DB에 `immutable=1`을 사용하지 않습니다.
- **KakaoTalk — 손쉬운 사용:** `com.kakao.KakaoTalkMac` 프로세스의 접근성 API만 읽습니다. 지원하는 채팅 목록 행의 이름·미리보기·시각·읽지 않은 수를 해석하고 등록한 각 이름과 일치하는 한 행씩 전달합니다. 한 이름의 후보가 여러 개면 그 대상은 거부합니다. 목록 구조를 찾는 동안 카카오톡 목록의 다른 행 정보도 일시적으로 메모리에 들어갈 수 있습니다. 시스템 전체나 다른 앱의 접근성 트리는 탐색하지 않습니다. 수신 관측은 클릭·채팅 선택·스크롤·키 입력·앱 활성화 같은 접근성 동작을 수행하지 않습니다. 말풍선을 사용자가 클릭했을 때는 별도로 카카오톡을 활성화합니다.
- **KakaoTalk 개별 알림 — 전체 디스크 접근:** `~/Library/Group Containers/group.com.apple.usernoted/db2/db`를 시스템 SQLite의 `mode=ro`와 `SQLITE_OPEN_READONLY`로 엽니다. 이미 Messages용 전체 디스크 접근을 허용했다면 같은 권한을 사용합니다. SQL에서 앱 번들 전체가 `com.kakao.KakaoTalkMac`과 대소문자 구분 없이 같은 레코드만 요청하고, plist의 앱 번들도 다시 검증합니다. 로컬 설정 이름과 정확히 일치하거나 뒤에 이모지만 붙은 제목만 허용하며, 비어 있지 않은 부제목은 그룹 대화 가능성이 있어 거부합니다. 제목 필터 과정에서 다른 카카오톡 연락처의 알림 payload도 메모리에 일시적으로 들어갈 수 있지만 전달하거나 저장·로그하지 않습니다. 다른 앱의 알림 payload는 SQL 조회 대상으로 삼지 않습니다.

권한이 없으면 고정된 상태 문구를 표시하고 필요한 경우 실행당 한 번 안내합니다. 개별 알림 DB만 읽을 수 없고 AX 목록이 정상이면 목록 경로를 계속 사용하며 상태 줄에 개별 알림용 전체 디스크 접근이 필요하다고 표시합니다. 메시지 연락처가 비어 있거나 카카오톡 이름이 비어 있으면 해당 reader는 DB·접근성을 조회하지 않습니다. 앱이 종료된 동안 대신 관측하는 데몬은 설치하지 않습니다. 손쉬운 사용과 전체 디스크 접근은 macOS가 넓은 권한으로 부여하므로 위 범위는 이 코드의 사용 범위이며 OS가 이 앱에 강제하는 연락처별 접근 제한은 아닙니다.

카카오톡 창 안에 포함된 광고 등 다른 프로세스 소유의 접근성 하위 트리는 소유 PID 확인 후 속성·자식을 읽지 않고 제외합니다. 채팅 목록 안에서 소유 프로세스가 바뀌면 불완전한 관측으로 처리하며 이벤트나 읽음을 만들지 않습니다. 카카오톡이 선택적 설명·식별자·제목 조회에 돌려주는 `.failure`만 누락으로 취급하며, 실제 텍스트·자식·좌표 조회 오류는 계속 거부합니다. 이름·미리보기·시각·배지의 역할과 위치가 불명확하면 전달하지 않습니다.

알림센터 DB도 변경 SQL·읽기/쓰기 재시도·체크포인트·원본 파일 권한 변경을 수행하지 않고, 라이브 WAL 변경을 관측하기 위해 `immutable=1`을 사용하지 않습니다. 알림을 지우거나 읽음으로 표시하지 않습니다. 첫 성공한 조회, 권한 복구와 DB 교체는 새 기준 상태를 잡아 과거 기록을 재생하지 않습니다. 개별 레코드와 마지막 수정 상태를 식별하지만, OS가 삭제한 알림이나 관측 전에 같은 레코드에 덮어쓴 중간 내용은 복구하지 못합니다. 이 DB는 macOS 내부 형식이므로 형식·권한이 달라지면 읽기를 보류하고 AX 경로를 사용합니다.

개별 알림의 생성·본문은 카카오톡의 macOS 알림 허용·배너/알림 표시·내용 미리보기 설정에 의존합니다. 숨겨졌거나 식별할 수 없는 알림은 본문을 추측하지 않습니다. 개별 알림을 우선하고 대응 알림이 없으면 잠시 뒤 AX 미리보기로 대체하며, 읽음 판정에는 계속 AX 배지 관측을 사용합니다. 알림센터에서 레코드가 사라진 사실은 읽음으로 해석하지 않습니다. 양쪽 경로의 시간·본문을 보수적으로 대응시켜 중복을 억제하므로 일부 중복은 남을 수 있습니다. 더 오래된 대응 후보 때문에 실제 새 알림·AX 수신을 버리지 않도록 관측 시각을 함께 확인합니다.

## 빌드 서명과 macOS 권한

현재 이 Mac의 빌드는 전용 로컬 인증서 서명을 사용합니다. [고정 코드 서명 가이드](SIGNING.md)에 따라 로그인 키체인의 같은 인증서·개인키를 재사용하며, 사용자 로컬 `signing.plist`에는 공개 인증서 지문과 키체인 경로만 저장합니다. 개인키·키체인 비밀번호는 저장소나 로그에 남기지 않습니다. 서명 설정이 없는 환경의 기본 빌드는 ad-hoc이며, 설정된 인증서로 서명하지 못하면 자동으로 ad-hoc으로 바꾸지 않고 실패합니다.

고정 서명은 시스템 설정의 손쉬운 사용·전체 디스크 접근 승인을 대신하지 않습니다. 처음 인증서 서명으로 전환한 설치본은 권한을 다시 허용하고, 이후 업데이트에서도 실제 AX/DB 접근을 확인해야 합니다. 로컬 인증서는 Apple Developer ID 서명·공증·배포를 제공하지 않습니다.

## 경계에서 검증하는 것

웹페이지 DOM과 content script 메시지를 신뢰하지 않습니다. 서비스 워커는 메시지 보낸 확장 ID, 페이지 출처, 최상위 프레임, 이벤트 형식, sender 허용 목록을 확인합니다. 테스트 이벤트는 사용자가 확장 프로그램 설정에서 명시적으로 실행하는 별도 동작입니다.

Swift 호스트에서도 버전, 타입, 문자열 길이, username, eventId, 타임스탬프, Instagram 대화 URL을 다시 검증합니다. **Chrome에서 카카오톡·메시지 이벤트나 해당 소스의 읽음 표시를 주입할 수 없습니다.** 기존 이벤트에서 `source`가 없으면 Instagram으로 해석하고, 다른 로컬 소스는 펫 앱 내부 reader만 생성합니다. 소스와 대화 키를 함께 사용하므로 한 대화의 읽음이 다른 소스의 말풍선을 지우지 않습니다.

수신한 문자열을 셸 명령으로 실행하지 않습니다. 앱은 표시할 내용을 평문으로 처리합니다. 클릭 대상은 검증된 Instagram HTTPS 대화 URL, 고정된 카카오톡 앱, 로컬 설정 연락처와 일치하는 메시지 `sms:` URL로 제한합니다. 메시지 archive는 지원하는 문자열 형식만 제한적으로 디코딩하며 임의 클래스나 첨부 파일을 실행하지 않습니다. Chrome도 content script 입력과 메시지 보낸 주체를 검증하도록 권장합니다. [Chrome extension security](https://developer.chrome.com/docs/extensions/develop/security-privacy/stay-secure)

Native Messaging 호스트 등록은 정확한 한 확장 프로그램 ID를 허용하며 와일드카드가 없습니다. 실행 파일은 절대 경로로 지정됩니다. 이 프로젝트는 일반 Google Chrome의 사용자별 등록 경로를 사용합니다. 브라우저 종류나 별도 user-data-dir를 바꾸면 등록 경로도 확인해야 합니다. 프로토콜은 길이 헤더와 UTF-8 JSON을 사용하며 일반 로그를 stdout에 출력하면 연결이 깨집니다. [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)

앱의 상대방 설정은 **앱 → 로컬 호스트 → 등록된 확장 프로그램**으로만 동기화합니다. `config` 요청도 같은 확장 origin 검사 뒤에 처리하며 요청마다 `sources.json`의 Instagram username·thread 번호 목록을 다시 검증합니다. 응답에는 Instagram의 두 목록 문자열 또는 앱 관리 없음 표시만 포함하고, 메시지 전화번호·이메일, 카카오톡 이름, 다른 로컬 설정은 반환하지 않습니다. 확장도 응답의 버전·타입·문자열과 목록 형식을 검증하며 잘못된 응답으로 기존 설정을 바꾸지 않습니다. Instagram 설정을 확장에서 앱 파일로 쓰는 요청은 없습니다.

각 입력란은 쉼표로 구분한 최대 100개 항목을 받고, 구분 공백을 제거한 정규화 문자열로 저장합니다. Instagram username은 항목별로 ASCII 영문 소문자·숫자·점·밑줄 1~30자, thread 번호는 항목별로 ASCII 숫자 1~128자리로 제한합니다. ID와 번호의 개수·순서는 대응해야 하고 thread 번호 중복은 거부합니다. 같은 ID의 다른 thread 등록은 허용하며 확장 허용 목록에서 ID만 중복 제거합니다. 메시지 연락처는 각각 정규화하고 카카오톡 이름도 각각 검증하며, 이 두 목록의 정규화된 중복은 제거합니다. 중간·끝의 빈 항목이나 어느 한 값의 검증 실패도 전체 저장을 거부하므로 일부 연락처만 적용되지 않습니다. 전체 설정 파일의 크기는 16 KiB로 제한합니다.

앱이 관리하는 Instagram 비활성 상태는 두 빈 문자열로 명시합니다. `instagram` 항목이 없는 기존 파일에서 앱의 두 Instagram 입력란을 수정하지 않으면 이 상태를 보존해 확장 수동 설정을 유지합니다. 처음 입력란을 수정하면 앱 설정을 사용하며, 두 목록을 비워 저장하면 명시적으로 비활성화합니다. 앱의 Instagram 값이 있으면 수동 허용 목록·대화 매핑은 별도로 보존하되 실제 감지에는 앱 값이 우선합니다. 설정 동기화 오류는 고정된 진단 상태로 표시하고 입력 값이나 파일 내용을 오류 로그에 넣지 않습니다.

## 메시지가 저장되는 곳

카카오톡 표시 이름과 메시지 전화번호·이메일 목록은 **사용자 로컬의 `~/Library/Application Support/InstagramPet/sources.json`에만** 보관합니다. 앱에서 관리하는 Instagram username·thread 번호 목록도 이 파일에 저장하며, 이 두 목록은 동기화 후 Chrome 확장 storage에도 남습니다. JSON 필드 이름과 문자열 타입은 기존과 같고 내부에서 대상 배열로 해석합니다. 실제 값을 저장소·fixture·스크린샷·보고서에 복사하지 않습니다. 파일이 없으면 로컬 소스는 꺼지며 설치 스크립트는 이 파일을 덮어쓰지 않습니다.

펫 우클릭 **설정…** 창은 현재 앱 값을 표시하고 저장 전 세 소스 입력을 검증합니다. 실패하면 오류를 창에 표시하고 기존 파일을 유지합니다. 파일 읽기·저장은 `O_NOFOLLOW`를 사용하고 심볼릭 링크·다른 소유자·일반 파일이 아닌 대상·과도한 크기를 거부합니다. 저장은 같은 앱 데이터 폴더의 임시 파일을 권한 `600`으로 작성한 뒤 원자적으로 교체합니다. 상위 앱 데이터 폴더는 `700`입니다. 메시지·카카오톡은 대상별 child reader를 묶어 관측하고, 등록 대상 추가·삭제 시 계속 등록된 대상의 reader는 재사용합니다. 제거된 대상의 말풍선·대기 상태만 정리하므로 같은 소스의 다른 등록 상대와 다른 소스는 유지합니다. 대화 키로 읽음을 분리하고 메시지 말풍선 클릭도 그 대화와 일치하는 등록 연락처를 선택합니다. 외부 편집기로 파일을 직접 바꾼 경우에는 앱을 다시 실행합니다. 설정 저장은 macOS 권한 승인이나 원본 메시지 DB 변경을 수행하지 않습니다.

본문은 전달을 위해 제한된 대기 큐에 잠시 남을 수 있습니다. 확장 프로그램 대기 큐는 최대 100개, 최대 5분이며 초과 시 가장 오래된 항목을 버리고 진단 정보를 남깁니다. Chrome이 종료되어도 로컬 저장소에 대기 이벤트가 남을 수 있습니다. 호스트가 수락한 이벤트는 `~/Library/Application Support/InstagramPet/inbox/`에 최대 200개, 24시간 보관하며 큐가 가득 차면 새 이벤트를 거부합니다. 시간 만료 정리는 다음 큐 접근 시 이루어지므로, 종료된 프로그램이 정각에 디스크 파일을 지우는 방식은 아닙니다.

로컬 두 소스도 같은 private 큐를 공유합니다. 큐에는 메시지 본문과 소스, 관측 시각, 식별자가 포함됩니다. 카카오톡·메시지의 `sender`와 표시 이름에는 고정된 소스 이름을 사용하고, 대화 키에는 설정한 이름·정규화한 연락처의 SHA-256 해시를 사용합니다. `reads/`에는 소스·대화 키·읽음 시각만 저장하며 본문을 넣지 않습니다. 해시는 암호화가 아니며 추측 가능한 연락처의 비밀성을 보장하지 않습니다. 본문 안에 이름·연락처가 포함된 경우에는 그 본문이 큐에 남을 수 있습니다.

호스트의 ACK는 로컬 큐 수락입니다. 사용자가 화면에서 봤다는 보증이 아닙니다. 앱은 표시 전까지 이벤트를 디스크 큐에 유지하고 말풍선을 표시할 때 파일을 삭제합니다. 실행 중 메모리에는 최근 말풍선과 대기 메시지가 남을 수 있습니다. 본문 없는 중복 식별 기록은 Chrome 최대 500개, 호스트 최대 4,096개이며 24시간의 제한을 둡니다.

로컬 child reader는 큐가 가득 찼을 때 재시도하도록 **대상별·reader별 최대 200개**의 이벤트를 메모리에 유지합니다. 이 수치는 여러 상대를 합친 전역 상한이 아니며, 등록 대상이 늘면 관측 비용과 메모리 대기량도 늘어납니다. 공유 디스크 큐의 상한은 별도로 전체 200개입니다. 각 카카오톡 대상의 알림 경로와 AX 경로는 각각 수락 대기 상태를 유지하되 같은 private 큐로 전달합니다. 알림·수정 식별자의 내용 없는 중복 기록은 각 reader의 메모리에서 12시간 유지하고 4,096개로 정리합니다. 양쪽 경로를 대응시키는 별도 캐시는 최근 5초의 본문을 메모리에서 사용합니다. 카카오톡 수락 대기와 메시지 읽음 추적은 12시간으로 제한합니다. 화면의 말풍선은 기존과 같이 관측 후 12시간이 지나면 만료됩니다. 앱을 종료하면 메모리 상태는 사라지며, 관측하지 못한 중간 메시지를 전체 이력으로 복원하지 않습니다.

일반 진단 로그에는 본문·실제 계정명·로컬 연락처를 쓰지 않습니다. 소스 상태 줄에는 권한·관측 상태 같은 고정된 문구만 표시합니다. 메시지 미리보기는 펫 말풍선에 표시되므로 화면을 공유할 때는 숨기기 또는 표시 중단 기능을 사용합니다. 로컬 파일 접근 제한은 다른 macOS 사용자와의 분리를 위한 것으로, 같은 사용자 권한으로 실행되는 악성 프로그램까지 막는 암호화 경계가 아닙니다.

## 제거 및 초기화

루트 README의 제거 절차로 Native Messaging 등록과 앱·호스트를 지우고, Chrome에서 확장 프로그램을 제거합니다. 보관 데이터 삭제를 선택하면 `sources.json`을 포함한 Application Support 아래 프로젝트 전용 데이터도 삭제합니다. 원본 메시지 DB·카카오톡 데이터·공유 알림센터 DB는 삭제하지 않습니다. 필요하면 시스템 설정에서 펫의 손쉬운 사용·전체 디스크 접근 권한도 해제합니다. 재설치는 허용 목록·대화 매핑·로컬 소스 설정·전달 대기 상태를 다시 확인한 뒤 사용합니다.

실제 메시지, 계정명, 대화 URL, 쿠키·토큰, 전체 DOM 또는 HAR를 버그 보고에 넣지 않습니다. 구조 변경 보고는 [DOM-DRIFT.md](DOM-DRIFT.md)의 가짜 값 fixture 절차를 사용합니다.
