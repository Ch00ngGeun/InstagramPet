# 검증 절차

이 문서는 **자동화 검증**과 **로그인된 실제 Instagram 화면 검증**을 구분합니다. 저장소의 DOM fixture는 개인정보가 없는 합성 HTML입니다. 테스트 통과는 이 HTML과 구현한 상태 전이가 일치한다는 뜻이며, 현재 Instagram의 모든 계정·언어·A/B 화면에서 작동했다는 뜻이 아닙니다.

## 1. 자동화 검증

프로젝트 루트에서 실행합니다.

```sh
cd extension
npm ci
npm test
cd ../macos
swift run PetCoreChecks
swift run PetSourcesChecks
cd ..
./scripts/build-app.sh
python3 scripts/test-native.py
python3 scripts/test-install.py
python3 scripts/test-app.py
```

확장 프로그램 테스트는 파싱과 감지 상태를 확인하고, `PetCoreChecks`는 Foundation만 사용하는 실행형 검사로 이벤트 검증·로컬 큐·중복 처리를 확인합니다. 전체 Xcode의 XCTest 모듈 없이 Apple Command Line Tools로 실행할 수 있도록 구성했습니다. 앱을 빌드한 뒤 프로젝트 루트에서 `./scripts/test-native.py`로 Native Messaging 프레임 통합 검사도 실행합니다. 빌드 명령은 루트 README를 따릅니다. 테스트 결과를 보고할 때 실행한 명령, 종료 코드, 실제 테스트 수를 함께 기록합니다.

말풍선 모퉁이 회귀만 실행하려면 `python3 scripts/test-app.py AppPipelineTest.test_tucked_bubbles_settle_at_every_corner_without_hidden_pet_distortion`을 사용합니다. 실제 애니메이션으로 네 모퉁이에서 일반·장문 메시지 12개를 연속 추가하며, 합성 렌더 PNG 8개와 수치 보고서를 `work/bubble-geometry/`에 보존합니다.

최소 회귀 사례:

| 입력 / 조작 | 기대 결과 |
| --- | --- |
| 첫 DOM 스냅샷의 기존 DM | 전송하지 않고 기준 상태로 기억 |
| 등록된 계정의 새 수신 메시지 | 검증된 이벤트 한 개 전달 |
| 등록하지 않은 계정, 표시 이름만 일치 | 전달하지 않음 |
| 본인이 보낸 메시지 또는 발신 방향 불명 | 전달하지 않음 |
| 같은 스냅샷 재검사 / React 노드 교체 | 다시 전달하지 않음 |
| 문구가 같은 서로 다른 새 메시지 | 확실한 별도 메시지 식별자가 있으면 각각 전달 |
| 이전 메시지 더 보기 / 위로 스크롤 | 과거 메시지 알림을 만들지 않음 |
| URL 전환 / 탭 복원 / 긴 중단 후 재개 | 새 기준 상태를 만들고 과거 내용 재전송하지 않음 |
| 읽지 않은 inbox 미리보기 변경 | 미리보기 이벤트로 표시; 전체 메시지 수신으로 주장하지 않음 |
| 모르는 DOM / 모호한 그룹 | 추측하지 않고 진단 정보 표시 |
| 같은 eventId를 두 탭이 전달 | 중복 표시하지 않음 |
| 호스트 없음 / ACK 전 연결 끊김 | 오류 표시 및 제한된 큐에서 재시도 |
| 비정상 URL / 너무 큰 프레임 / 깨진 JSON | 실행·링크 열기 없이 거부 |

## 2. 계정 없는 로컬 연결 시험

1. README에 따라 앱을 빌드하고 Chrome에 `extension/`을 압축해제 확장 프로그램으로 로드합니다.
2. Chrome에서 보이는 실제 확장 프로그램 ID로 Native Messaging 호스트를 등록합니다. 폴더 이동이나 Chrome 프로필 변경으로 ID가 달라졌다면 다시 등록합니다.
3. 확장 프로그램 설정의 연결 확인을 실행합니다. 성공은 Chrome이 호스트와 통신할 수 있다는 뜻입니다.
4. 설정 화면에서 명시적인 테스트 메시지를 보냅니다. 펫 말풍선에 테스트임이 드러나는 메시지가 표시되어야 합니다. 이 시험은 Instagram 감지 테스트가 아닙니다.
5. 말풍선을 닫기, 펫 드래그, 메뉴에서 숨기기/다시 표시, 여러 테스트 메시지 순차 표시, 앱 종료 후 재실행을 확인합니다.
6. 호스트를 아직 등록하지 않은 설치 단계에서는 연결 확인이 오류를 표시하고 UI는 계속 응답해야 합니다. 이미 등록을 마쳤다면 이를 시험하려고 실제 등록을 지울 필요는 없습니다. `./scripts/test-native.py`는 임시 환경에서 잘못된 확장 ID와 호출 출처 누락을 검사합니다. Native Messaging 등록은 같은 사용자 계정의 일반 Chrome 프로필 사이에 공유될 수 있습니다.

호스트의 `ack`는 **이 Mac의 로컬 큐에 수락했다**는 뜻입니다. 앱이 실행되지 않았거나, 사용자가 펫을 숨겼거나, 큐가 아직 처리 중이면 화면에는 곧바로 보이지 않을 수 있습니다.

## 3. 실제 Instagram 시험 — 사용자가 수행

다른 계정에서 보내는 메시지는 사용자가 직접 보냅니다. 자동화 테스트는 실제 계정으로 메시지를 보내지 않습니다.

1. Chrome에서 Instagram에 로그인하고 DM 페이지를 엽니다. 확장 프로그램 설정에는 상대방의 표시 이름 대신 정확한 `@username`을 등록합니다.
2. 상대와의 1:1 대화를 엽니다. 구현이 요구하는 대화 확인/매핑을 완료하고 진단 상태를 확인합니다. 그룹 대화는 지원하지 않으므로 시험 대상에서 제외합니다.
3. 기존 메시지가 알림으로 나타나지 않는지 확인합니다. 설정 저장·페이지 로드·대화 이동 뒤 DOM이 안정된 상태로 최소 5초 기다립니다. 시작 시 약 3초의 안정화 구간에 도착한 내용은 기존 기준 상태로 취급될 수 있습니다. 그 뒤 새 수신 메시지를 한 개 보내고 펫의 발신자·본문·대화 링크가 맞는지 봅니다.
4. 본인 계정에서 답장을 보냅니다. 펫이 본인의 답장을 수신 DM으로 표시하면 실패입니다.
5. 허용 목록에 없는 다른 계정에서 메시지를 보냅니다. 알림이 나타나면 실패입니다.
6. 상대가 같은 짧은 문구를 두 번 보냅니다. 감지 한계가 있으면 누락으로 기록하며 성공으로 처리하지 않습니다.
7. 대화 목록으로 돌아가 읽지 않은 미리보기를 바꿉니다. 표시된다면 미리보기임을 확인합니다. 빠른 연속 메시지의 중간 본문이 DOM에 남지 않을 수 있습니다.
8. 페이지 새로고침, 대화 이동, 과거 내역 스크롤, 확장 프로그램 다시 로드 후 기존 DM이 다시 나타나는지 확인합니다.
9. Instagram 탭을 열린 채로 다른 Chrome 탭 또는 다른 앱을 사용합니다. 렌더링과 연결이 유지되는 동안 감지되는지 확인하고 지연을 기록합니다. 백그라운드 감지 시간을 보장하지 않습니다.
10. Instagram 탭을 닫거나 Chrome을 종료한 뒤 새 DM을 보냅니다. 이 상태에서 감지하지 않는 것이 이 MVP의 예상 동작입니다. 다시 열었을 때 이전 내용을 새 DM으로 재생하지 않는지도 확인합니다.
11. 탭 강제 삭제, 절전, 네트워크 끊김 후 복귀를 시험합니다. 그동안의 메시지 누락은 현재 구조의 한계로 기록합니다.

## 4. 카카오톡·메시지 실제 수신 시험

1. README의 로컬 소스 설정과 설치된 펫 앱의 권한을 확인한 뒤 다시 실행합니다. 시작 기준 상태가 잡힌 후, 설정된 상대가 새 1:1 메시지를 보내도록 합니다. 본인 발신이나 시작 전 과거 내역이 나타나면 실패입니다.
2. 카카오톡 대화를 읽지 않은 채 짧은 문구, 같은 문구 반복, 장문 5개를 차례로 받습니다. 알림 허용·내용 미리보기를 켠 상태에서 개별 말풍선과 도착 순서를 확인합니다. 이미 떠 있는 말풍선 때문에 새 수신이 4초씩 지연되면 실패입니다. 보고에는 본문 대신 전달 개수와 지연 숫자만 남깁니다.
3. 개별 OS 알림이 없는 환경에서는 AX 목록 경로를 시험합니다. 최소화하지 않은 목록에 대상 행을 표시하되 대화를 직접 열지 않습니다. 미리보기 변화와 안정된 배지 증가를 확인하고, 빠른 수신 사이 사라진 중간 본문은 AX의 한계로 구분합니다.
4. Instagram·Messages 말풍선이 함께 있는 상태에서 카카오톡만 읽습니다. 목록에서 배지 소멸을 연속 확인한 뒤 카카오톡 말풍선만 없어져야 합니다. 알림센터에서 알림을 지우는 동작만으로 읽음 처리되면 실패입니다. Messages 대화를 읽을 때도 다른 소스의 말풍선이 유지돼야 합니다.
5. 실제 수신 지연과 [합성 지연 측정](VALIDATION.md)의 범위를 구분합니다. Chrome은 [CHROME-LATENCY.md](CHROME-LATENCY.md)의 정책·숨겨진 탭 프로브 절차를 참고하며, 프로브 수치를 실제 DM 전체 전달 시간으로 기록하지 않습니다.

## 결과 기록 양식

```text
시험 일시 / macOS / Chrome 버전:
확장 프로그램 버전:
Instagram 표시 언어 / URL 유형 (실제 대화 ID는 생략):
감지 상태 / DOM adapter 상태:
시험 항목:
기대 결과:
실제 결과 / 지연:
통과 / 실패 / 미지원:
개인정보를 제거한 재현 fixture 경로:
```

버그 보고에 실제 메시지, 전체 DOM, 계정명, 대화 URL, 쿠키, 액세스 토큰, HAR 파일을 붙이지 않습니다. 구조 변경 대응은 [DOM-DRIFT.md](DOM-DRIFT.md)를 따릅니다.

Chrome의 content script는 실제 웹페이지 DOM을 읽습니다. 따라서 닫힌 탭에 대한 감지 경로는 이 구현에 없습니다. [Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)
