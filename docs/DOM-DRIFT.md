# Instagram DOM 변경과 감지 범위

Instagram은 이 확장 프로그램을 위한 안정적인 DM DOM 계약을 제공하지 않습니다. 역할(`role`), 접근성 레이블, 링크, 메시지 ID 같은 구조를 조합해도 계정별 실험, 언어, 화면 크기, 메시지 유형에 따라 달라질 수 있습니다. 이 저장소의 fixture는 **합성 예제**이며, 현재 로그인된 Instagram에서 채집하여 검증한 스냅샷이 아닙니다.

## 감지의 의미

- **열린 1:1 대화:** 화면 DOM에 새 수신 메시지와 발신자 근거가 있어야 합니다. 색상, 좌우 위치, 표시 이름 하나만으로 상대를 추정하지 않습니다.
- **inbox:** 새로 바뀐 읽지 않은 대화의 미리보기를 관측합니다. 여러 메시지가 한 미리보기로 합쳐지면 각 본문을 복구할 수 없습니다. 메시지 ID나 시각 없이 같은 미리보기 문구가 반복되면 별도 새 메시지로 구분하지 못할 수 있습니다. 미리보기만으로 정확한 발신자를 식별할 수 없으면 보내지 않습니다.
- **그룹·사진·음성·삭제·사라지는 메시지:** 표시된 텍스트와 식별 정보만 사용할 수 있습니다. 그룹 제목을 개인 username으로 취급하거나 보이지 않는 내용을 추정하지 않습니다.
- **다른 앱 사용 중:** Instagram 탭이 살아 있고, 로그인과 DOM 렌더링이 유지되어야 합니다. 비활성 탭의 타이머 지연·삭제·네트워크 재연결로 지연 또는 누락될 수 있습니다.
- **탭 닫힘 / Chrome 종료 / 잠자기:** 실시간 감지하지 않습니다. Native Messaging은 이미 관측한 이벤트를 전달하는 통로이며 DM 수신 API가 아닙니다.

처음 로드한 내용은 기준 상태로만 저장합니다. 다시 로드·대화 이동·복원·긴 중단 이후에는 과거 메시지를 새 알림으로 재생하지 않는 쪽을 택합니다. 따라서 그 사이 도착한 일부 메시지를 의도적으로 놓칠 수 있습니다. DOM 감지로 완전한 메시지 이력을 보장할 수 없습니다.

Chrome은 content script가 페이지 DOM을 읽을 수 있도록 하고, `matches`에 맞는 페이지에 정적으로 삽입합니다. 이 범위가 닫힌 페이지의 메시지 수신까지 확장되지는 않습니다. [Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)

## 실패를 구분하는 순서

1. 확장 프로그램의 연결 확인과 테스트 메시지를 실행합니다. 여기서 실패하면 DOM보다 호스트 등록·앱 실행을 먼저 확인합니다.
2. 정확한 상대 username이 허용 목록에 있는지 확인합니다. 표시 이름은 중복될 수 있습니다. 설정에서 실제 1:1 대화의 `thread ID = username` 매핑을 확인하면, DOM이 계정명 대신 표시 이름만 노출하는 경우에도 신원을 명시할 수 있습니다. 매핑만으로 수신 방향을 확인할 수 있는 것은 아니므로 필요한 경우 검증한 incoming/outgoing selector도 설정합니다.
3. 로그인된 DM 페이지에서 확장 프로그램 진단 상태를 봅니다. 지원하지 않는 구조·발신자 불명·방향 불명은 별도 실패로 기록합니다.
4. 새 DM 하나만 시험합니다. 처음 표시된 기존 DM이 오지 않는 것은 기준 상태 처리일 수 있습니다.
5. DOM에 메시지가 있는지 사람이 확인합니다. 페이지 자체에 새 내용이 없으면 이 확장 프로그램은 가져올 수 없습니다.

문제 보고는 `연결 실패`, `지원하지 않는 DOM`, `필터 제외`, `기준 상태 처리`, `중복 제거`, `재시도 대기`, `실제 누락`을 구분합니다. 정상 연결을 DM 감지 성공으로 보고하지 않습니다.

## 개인정보 없는 구조 fixture 만들기

전체 페이지 저장, HAR 내보내기, React 내부 상태 덤프, 쿠키 복사는 하지 않습니다. 개발자 도구의 Elements에서 문제와 관련된 최소 메시지 컨테이너만 살펴봅니다.

1. 필요한 태그, `role`, 접근성 속성, 링크 형태, 시간 및 메시지 식별자 존재 여부를 기록합니다.
2. 공유 전 **새 HTML 파일에 구조만 재작성**합니다. 실제 `outerHTML` 전체를 첨부하지 않습니다.
3. 모든 계정명을 `fixture.sender`, 본문을 `fixture message`, 대화 ID를 `12345`, 메시지 ID를 `fixture-1` 같은 가짜 값으로 바꿉니다. URL·이미지 주소·토큰·추적 속성·인라인 스크립트는 제거합니다.
4. 문제 상황의 초기 스냅샷과 변경 후 스냅샷을 만듭니다. 수신/발신, 메시지 순서, unread 변화, 같은 문구 반복 여부를 명시합니다.
5. 실제 신원이나 대화 내용을 파일 검색으로 다시 확인한 뒤 테스트 fixture로 추가합니다.

## adapter 수정 원칙

수정 범위는 확장 프로그램의 DOM 파서와 해당 fixture 테스트입니다. 난독화된 CSS 클래스 하나만을 기준으로 넓은 수집을 추가하지 않습니다. 필터·큐·Native Messaging 검증을 우회해서 지원 범위를 넓히지 않습니다.

새 adapter에는 허용한 구조뿐 아니라 비슷한 발신 메시지, 탐색 메뉴, 그룹 제목, 표시 이름만 같은 다른 사용자, 과거 내역 삽입, DOM 노드 교체, 중복 실행을 거부하는 fixture를 함께 둡니다. 이후 실제 사용자의 1:1 대화에서 허용된 새 메시지 하나로 확인합니다. 자동화 fixture 통과와 실제 화면 확인은 따로 기록합니다.

서비스 워커는 중단될 수 있으므로 전달 대기 상태를 전역 변수만으로 보관해서는 안 됩니다. 재시도 큐와 수락 여부를 저장하고 다시 시작해도 복구하도록 구현합니다. [Chrome service worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)
