## 모퉁이 말풍선 애니메이션 재검증 (2026-11-11)

숨긴 펫의 이전 위치가 말풍선을 밀거나 테두리를 누르지 않도록 한 수정에 애니메이션 회귀 검사를 추가했습니다. 연속 도착으로 줄이 바뀔 때 Dictionary의 임의 순서로 충돌을 처리하면 말풍선이 목표에서 최대 약 88pt 벗어난 위치에 남을 수 있어, 실제 도착 순서대로 처리하도록 고정했습니다.

- `./scripts/build-app.sh`: release 앱·호스트 빌드 및 고정 인증서 서명 검증 성공.
- `python3 scripts/test-app.py`: **9/9 통과**. 기존 전달·읽음·설정·펫 기하 검사와 새 말풍선 검사를 포함합니다.
- 새 검사는 네 모퉁이 × 일반/장문 12개(소스별 4개)의 8경우에서, 메시지를 하나씩 추가하고 실제 `place(animated: true)`를 실행합니다. 마지막 240 tick의 끝 20 tick에서 현재 위치와 목표의 차이, 전체 12개 유지·화면 안 배치를 검사합니다.
- 같은 화살표 위치에서 숨긴 펫을 화면 밖에 두거나 말풍선과 겹치는 이전 위치에 두어도 실제 테두리 spline이 일치했습니다. 최대 목표 편차는 부동소수점 오차 수준(약 0.00000000000003pt), 최대 테두리 좌표 차이는 0pt였습니다.
- 별도 임시 복제본에서 숨긴 펫의 충돌을 다시 켜면 같은 검사가 **실패**했습니다(최대 목표 편차 약 182pt, 테두리 좌표 차이 약 123pt). 수정의 퇴행을 감지하는 것을 확인했습니다.
- 합성 데스크톱 PNG 8개를 `work/bubble-geometry/`에 보존합니다. 네 모퉁이의 대표 렌더를 열어 얇게 찌그러진 테두리나 본문을 가로지르는 잘림이 없는 것을 확인했습니다.

이 검사는 실제 AppKit 레이아웃·충돌·spring·테두리 렌더를 실행하지만, 사용자 화면의 새 메시지 수신이나 다중 모니터를 검증한 것은 아닙니다.

`PetCoreChecks`는 `source`가 없는 기존 이벤트를 Instagram으로 해석하는 호환성, 소스별 대화 키 검증, 읽음·중복 식별자의 소스 격리, 로컬 설정 검증과 전화번호 정규화, 소스별 클릭 목적지를 확인합니다. Chrome Native Messaging 경계는 Instagram 이벤트와 읽음만 수락하고 카카오톡·메시지 주입을 거부하도록 제한했습니다.

로컬 reader 검사는 실제 사용자 데이터 대신 합성 SQLite DB와 `KakaoAXNode` 트리를 사용합니다. 메시지는 과거 이력 baseline, 1:1 연락처·발신 방향 필터, 일반/attributed 본문, 첨부 종류, 뒤늦은 본문, WAL 변경, 잠금 후 재시도, DB 교체, 대기 큐와 읽음 watermark를 검사합니다. 앱 재시작 시 이미 수락한 대기 이벤트를 원본 행에 다시 연결해 읽음을 반영하되, 다른 연락처·교체된 DB의 같은 행 번호를 잘못 연결하지 않는 회귀 검사도 포함합니다. 카카오톡은 이름 뒤 이모지 경계, 중복 후보 거부, 숫자·시각처럼 생긴 미리보기 구분, 최초 상태 억제, 미리보기·시각 변화, 배지 소멸의 연속 확인, 불완전 트리·권한 없음·앱 종료·PID 변경, 날짜 표시 변경과 큐 용량 회복을 검사합니다.

카카오톡 채팅 목록을 읽기 전용으로 실측해 `AXRow → AXCell` 안의 이름·시각·배지 `AXStaticText`, 미리보기 `AXScrollArea → AXTextArea`, 선택적 프로필 버튼과 이미지 구조를 확인했습니다. 배지는 설명·식별자가 없는 `AXStaticText`이며, 이름 옆의 숫자는 그룹 인원수로 나타날 수 있습니다. 실측 행은 305×74이고 미리보기의 접근성 프레임은 행 아래로 4pt 초과했습니다. 가짜 이름·본문을 넣은 새 회귀 6개 그룹은 이 구조에서 시작 baseline·수신/재시도·읽음, 그룹 인원수 거부, 숫자/시각 미리보기, 장식 아이콘 생략, 불완전·중복 구조 및 과도한 13pt 프레임 초과 거부를 확인합니다.

카카오톡 목록 창이 최소화된 상태에서는 관측에서 제외됐고, 창을 복원한 뒤 읽기 전용 프로브와 네이티브 reader의 실제 AX 수집 경로에서 모두 `observing`을 확인했습니다. 이때 창 1개·노드 63개를 약 0.07초에 읽었고, 첫 기준 상태의 결과는 events 0·reads 0이었습니다. 이는 새 메시지 수신이나 읽음 전환 성공을 뜻하지 않습니다. 최종 release 설치본의 메뉴 상태와 업데이트 후 권한 유지는 별도로 확인해야 합니다.

실측 과정에서 선택적 `AXDescription`이 없는 요소가 `AXError.failure`(-25200)를 반환하고, 창의 광고 하위 트리가 별도 WebKit PID에 속하는 것을 확인했습니다. 선택적 설명·식별자·제목의 `.failure`만 누락으로 허용하고, 실제 텍스트·자식·좌표 오류는 거부하도록 보완했습니다. 다른 PID의 목록 밖 하위 트리는 속성·자식 조회 없이 제외하며, 목록 안에서 발견되면 불완전한 관측으로 거부합니다.

앱의 혼합 소스 smoke 시나리오는 Instagram 2개·Messages 2개·KakaoTalk 1개와 대기 메시지를 구성하고 각 대화를 읽을 때 해당 소스·대화만 제거하는지 확인했습니다. 표시 개수는 `5 → 4 → 2 → 0`, 대기 개수는 `3 → 2 → 1 → 0`이며, 시간 순서·읽음 시각의 역행 방지·가득 찬 큐에서의 회복도 통과했습니다. `--render-scenarios`로 38개 PNG를 생성하고 `1b-mixed-sources`와 `1c-mixed-after-kakao-read`를 열어 흰 배경·Instagram 그라데이션·카카오톡 노랑·메시지 초록 테두리와 카카오톡 읽음 후 나머지 4개 보존을 확인했습니다. 자동 smoke·렌더는 실제 메시지 DB나 카카오톡 접근성 정보에 접근하지 않습니다. 알림 지연 smoke만 격리된 합성 DB에서 실제 notification reader를 실행합니다.

최종 수정 앱을 전용 인증서로 서명해 설치·재실행했습니다. 코드가 달라진 두 앱 빌드의 designated requirement가 같고, 이전 requirement로 새 빌드와 설치본을 검증했습니다. 최신 갱신에서도 이전 설치본과 서명 requirement가 같고 앱·호스트 서명 검사가 통과했습니다. `sources.json`, `signing.plist`, `config.json`의 바이트와 기존 600 권한을 보존했습니다. 업데이트 후 같은 서명의 네이티브 AX 관측은 아래 100회 측정에서 성공했으며, 실제 DB 접근과 원본 앱 읽음은 별도 시험 범위입니다.

**카카오톡·메시지의 실제 수신·원본 앱의 읽음·클릭 이동은 미검증입니다.** 카카오톡은 실측한 목록 구조와 네이티브 AX 관측을 확인했으며, 새 메시지·읽음 전환을 따로 시험해야 합니다. 실제 메시지 연락처는 사용자 로컬 설정에만 저장합니다. README의 빈 연락처는 비활성 설정 예시이며, 실제 수신은 설치된 앱의 전체 디스크 접근을 허용한 뒤 새 1:1 메시지로 시험해야 합니다. 권한을 부여했다는 사실이나 합성 검사 통과를 실제 수신 성공으로 간주하지 않습니다. 고정 서명 준비와 빌드 간 requirement 호환 시험은 [SIGNING.md](SIGNING.md)를 참고하세요.

## 지연·연속 수신 개선 후 재검증 (2026-11-07)

앱은 이전 말풍선을 읽도록 최대 4초씩 기다려 장문 5개 합성 수신의 마지막 표시가 16,196.5ms까지 늦어졌습니다. 이 대기를 제거해 이미 읽지 않은 말풍선이 있어도 새 수신을 즉시 반영하고 관측 시각 기준 최근 5개를 유지합니다. 로컬 소스와 큐는 약 0.5초마다 확인합니다.

| 측정 | 조건 | 결과 |
| --- | --- | --- |
| 기존 큐 → 실제 AppKit 말풍선 | 합성 1,000자 5개, 이전 메시지 미읽음 | 169.7~202.6ms, 5개 모두 표시 |
| 알림 DB WAL commit → 실제 reader → 큐 → 말풍선 | 합성 1,000자 5개, 각 레코드 UUID 별도 | 534.8~573.8ms, 5개 모두 표시 |
| 장문 경계 반복 | 합성 2,000자 5개 | 큐 156.5~189.6ms, 알림 532.9~576.8ms |
| 실제 KakaoTalk AX 캡처 | 고정 서명 앱, 100회 읽기 전용 관측 | 중앙값 43.5ms / p95 58.3ms / 최대 76.7ms |
| 실제 KakaoTalk reader 전체 poll | 같은 100회 관측 | 중앙값 44.6ms / p95 59.6ms / 최대 78.7ms |
| AX deadline·관측 상태 | 같은 100회 관측 | deadline 초과 0회, observing 100/100 |

```sh
python3 scripts/benchmark-delivery.py --source queue --messages 5 --length 1000
python3 scripts/benchmark-delivery.py --source notifications --messages 5 --length 1000
dist/InstagramPet.app/Contents/MacOS/InstagramPet --measure-live-ax
```

각 수치는 이 Mac에서 얻은 표본입니다. 합성 알림 DB는 실제 KakaoTalk의 네트워크 수신·OS 알림 생성 시간을 포함하지 않으며, 실제 새 수신을 요청하지 않고 측정했습니다. AX 실측도 새 메시지 도착부터 말풍선까지의 지연을 뜻하지 않습니다. 실제 서비스에서 2~3초 이내 전달된다는 보장은 아직 할 수 없습니다.

새 소스 회귀는 안읽음 유지 중 미리보기·시각 변경, 같은 문구·시각에서 배지 증가의 연속 확인, 뒤늦은 미리보기 교체와 일시적인 불완전 AX 트리 복구를 포함합니다. 알림센터 회귀는 정확한 앱·연락처 필터, 그룹·가려진 일반 제목 거부, 개별 UUID와 수정 레코드, WAL 변경, 잠금·DB 교체·큐 포화 재시도, 알림 삭제를 읽음으로 오인하지 않기, AX 대체 경로와 양방향 중복 억제를 확인합니다. 읽음 연동은 계속 AX 목록을 사용합니다.

Chrome의 실제 hidden DM 탭에서 250ms 타이머가 약 60초로 밀리는 현상을 확인했고, content script의 타이머 대기를 microtask로 대체했습니다. 확장을 다시 로드해 DM 탭 2개에 자동 폐기 방지를 적용했습니다. 사용자 범위의 `IntensiveWakeUpThrottlingEnabled=false` 프로필도 설치했으며, Chrome 정책 적용·재시작 전후 측정은 [CHROME-LATENCY.md](CHROME-LATENCY.md)에 기록합니다.

## 앱 설정 창 추가 검증 (2026-11-08)

펫 우클릭·메뉴 막대의 `설정…`에서 상대방을 편집합니다. 실제 사용자 값은 자동 검사에 사용하지 않았습니다. 폼 smoke는 임시 폴더의 가짜 연락처만 사용하고, reader를 생성하되 실제 DB·AX 관측은 시작하지 않습니다.

- `PetCoreChecks`는 인스타 관리 없음·명시적 빈 값 비활성·숫자 thread 검증, 정규화된 설정의 원자적 600 저장, 잘못된 입력의 원본 보존, symlink 루트·대상 거부를 확인했습니다.
- 실제 호스트 검사는 등록된 origin만 `config`를 요청할 수 있고, 같은 연결에서도 매번 파일을 재검증하며 Instagram 외 정보나 잘못된 값을 반환하지 않는지 확인했습니다.
- 확장 검사는 앱 우선순위·수동 값 백업과 복원, 빈 앱 선택의 비활성, 변경 없는 동기화의 무쓰기, 오래된 대기 이벤트 제거, 잘못된 응답·저장 실패·동시 요청 처리를 확인했습니다.
- 앱 폼 검사는 기존 값 채움, 잘못된 입력의 저장 거부, 유효한 저장과 변경한 reader만 교체, 다른 소스의 표시·대기 메시지 및 읽음 기록 보존, 비활성과 표시 경계의 선택값 검증을 확인했습니다.
- 쉼표 목록 검사는 여러 인스타 ID·번호의 순서 대응, 잘못된 개수·빈 항목·중복 대화 번호 거부, 여러 메시지 연락처의 클릭 목적지를 확인했습니다. 복수 연락처 reader는 읽음 격리·기존 baseline 재사용·추가와 제거·카카오톡 이모지 별칭 중복 거부를 검사하며, 앱 폼은 상대를 추가해도 기존 말풍선과 대기 메시지가 남는지 확인합니다.

기존 `sources.json`에 인스타 정보가 없고 인스타 입력칸을 건드리지 않으면 기존 Chrome 수동 설정을 유지합니다. 인스타 입력을 편집하면 앱 설정을 사용하며, 편집한 두 칸을 비워 저장하면 비활성화합니다. 이 검사는 실제 새 수신·권한·대화 클릭의 통제 시험을 대체하지 않습니다.
