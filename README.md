# Instagram Pet — macOS + Chrome MVP

실제 실행 가능한 **Swift/AppKit 플로팅 펫**, **Chrome Manifest V3 확장 프로그램**, **Swift Native Messaging 호스트**입니다. 등록한 여러 상대의 Instagram DM, 카카오톡 개별 알림·목록 미리보기, Apple 메시지(iMessage/SMS)를 같은 말풍선 공간에 표시합니다. 서버, API 키, Instagram 비밀번호 입력은 없습니다.

![실제 AppKit 뷰로 렌더링한 펫](docs/preview.png)

**Instagram 감지 조건:** Chrome에서 로그인한 Instagram **DM 페이지**가 열려 있고, 해당 메시지가 지원하는 DOM에 렌더링되어야 합니다. 탭 닫힘·탭 폐기·Chrome 종료·Mac 잠자기 중 DM을 실시간으로 가져오지 않습니다. 다른 앱이나 다른 탭을 사용하는 동안도 Instagram 페이지 렌더링과 연결이 유지되어야 하며 지연·누락될 수 있습니다. 처음 로드한 과거 내용과 복원 직후 내용은 알림으로 재생하지 않습니다. 카카오톡·메시지의 별도 조건과 권한은 [상대방 설정](#6-앱에서-상대방-설정)을 참고하세요.

자동화 테스트는 개인정보 없는 **합성 DOM·SQLite·접근성 트리 fixture**를 사용합니다. Instagram의 일부 실수신 확인 결과는 [검증 기록](docs/VALIDATION.md)에 있으며, 카카오톡·메시지의 실제 수신은 아직 검증하지 않았습니다. Instagram의 DOM은 계정·언어·A/B 실험별로 달라서, 기본 휴리스틱이 발신자나 수신 방향을 확인하지 못하면 **전송하지 않습니다**. 그때는 설정의 명시적인 1:1 대화 매핑과 검증된 선택자로 조정해야 합니다. [DOM 변경 대응](docs/DOM-DRIFT.md)을 확인하세요.

## 포함된 기능

- 배경이 투명한 AppKit `NSPanel`과 애니메이션 캐릭터, 드래그 위치 저장, 메뉴 막대 제어.
- 세 소스를 합쳐 최근 말풍선 최대 5개 표시, 관측 시간 순서 유지, 12시간 만료와 최근 말풍선 다시 보기.
- 흰 말풍선에 소스별 얇은 테두리와 은은한 빛: Instagram 그라데이션, 카카오톡 노랑, 메시지 초록.
- 말풍선 클릭 시 해당 앱 열기와 소스·대화별 읽음 제거. 카카오톡은 앱 활성화까지만 지원.
- 펫 숨김·메시지 표시 일시정지·로컬 데모·대기 메시지 삭제, 우클릭 **설정…** 창에서 여러 상대 등록·변경.
- Instagram은 정확한 username 허용 목록 사용. 표시 이름만 일치하는 사람은 통과하지 않음. 기본 허용 목록은 비어 있음.
- MutationObserver + 제한된 재검사, SPA/초기 로드 기준 상태, 수신·발신 구분, 미리보기와 본문 구분.
- DM 변경은 타이머 대기 없이 처리하고, 관측 대상 DM 탭의 자동 폐기를 방지합니다. 이 Mac의 절전 정책·측정 결과는 [Chrome 지연 기록](docs/CHROME-LATENCY.md)을 참고하세요.
- 확장 프로그램 재시도 큐와 중복 기록, Native Messaging 프레이밍·입력 검증, 로컬 Swift 큐와 수락 기록.
- 계정 없이 가능한 연결 테스트와 개인정보를 제외한 진단 정보.

iPhone 전용 앱, 답장 전송, Instagram 비공개 API 조회는 구현 범위에 포함되지 않습니다. 그룹 대화, 사진·음성의 원문 복원, 전체 메시지 이력 재생은 지원하지 않습니다.

## 1. 필요한 환경

- macOS 13 이상, 일반 **Google Chrome 120 이상**.
- Apple Command Line Tools 또는 Xcode의 Swift 도구. 최초 설치는 `xcode-select --install`.
- Node.js 20 이상과 npm: 확장 프로그램 **테스트에만** 필요. Chrome에 로드할 때 빌드나 npm이 필요하지 않습니다.
- Python 3: 설치 스크립트와 Native Messaging 통합 테스트. 이 Mac에서는 Apple Command Line Tools의 Python으로 검증했습니다.

`dist/`에는 검증한 Mac의 **Apple Silicon arm64** 실행 파일이 있습니다. 현재 이 Mac의 빌드는 전용 로컬 인증서로 고정 서명하며, Apple Developer ID 서명·공증 배포본은 아닙니다. Intel Mac에서는 아래 빌드 명령으로 다시 빌드하세요. 소스는 Swift Package라 Xcode에서 `macos/Package.swift`를 열어 살펴볼 수 있습니다.

## 2. 앱 빌드와 로컬 데모

터미널에서 압축을 푼 프로젝트 폴더로 이동합니다. 경로에 공백이 있으면 따옴표로 감싸세요.

```sh
cd "/path/to/InstagramPet"
./scripts/build-app.sh
open dist/InstagramPet.app
```

카카오톡·메시지 권한을 사용하는 앱을 반복해서 빌드할 때는 [고정 코드 서명 가이드](docs/SIGNING.md)를 먼저 확인하세요. `./scripts/prepare-local-signing.sh --trust-code-signing`으로 준비한 로컬 서명 설정이 있으면 빌드가 같은 인증서를 사용합니다. 설정이 없는 다른 Mac에서는 기본적으로 ad-hoc 서명합니다. ad-hoc에서 인증서 서명으로 처음 바꾼 설치본은 손쉬운 사용 권한을 한 번 새로 허용해야 하며, 이후 빌드 간 권한 유지도 실제 설치본에서 확인해야 합니다.

오른쪽 아래에 고양이가 나타나고 메뉴 막대에 발바닥 아이콘이 생깁니다. 아이콘 메뉴의 **Show Demo Bubble**로 로그인 없이 말풍선을 확인합니다. 캐릭터를 드래그해 이동합니다. 캐릭터는 항상 화면 안에 있고, 가장자리로 밀면 벽에 눌려 슬라임처럼 뭉개집니다(놓으면 출렁이며 복원). 화면 모서리로 밀어 넣고 놓을 때만 캐릭터가 모서리 화살표 뒤로 숨습니다(최대 1시간 뒤 자동으로 다시 나옴, 그동안에도 말풍선은 그 가장자리에 계속 뜸). 말풍선은 잘리지 않도록 캐릭터 가까운 화면 안쪽에 모입니다. 말풍선은 숨기기를 누르거나 해당 대화를 확인하거나 받은 지 12시간이 지나면 사라지며, 세 소스를 합쳐 최근 5개(오른쪽 최신, 머리 위, 왼쪽, 오른쪽 아래, 왼쪽 아래 순)가 시간과 함께 표시됩니다. Instagram 말풍선을 클릭하면 그 DM 대화가 Chrome에서 열리고(이미 열린 탭이 있으면 그 탭으로 전환), 그 대화의 말풍선은 사라집니다. Chrome에서 그 대화 탭을 직접 보고 있을 때도 사라집니다. 카카오톡·메시지의 클릭과 읽음 동작은 아래 로컬 소스 설정에 설명했습니다. 작은 슬라임 화살표는 무언가 숨겨져 있을 때(말풍선 숨기기·끌어서 숨김·펫 숨기기)만 나타나며, 언제든 짧게 클릭하면 숨김이 풀립니다. 화살표를 끌면 숨은 캐릭터와 함께 옮겨지고, 짧게 클릭해야 캐릭터가 다시 나옵니다. 캐릭터를 빠르게 끌면 말풍선은 통과되지 않고 밀려납니다. 말풍선·캐릭터 우클릭과 메뉴 막대의 **말풍선 잠깐 숨기기**/**펫 잠깐 숨기기**는 10분~1시간 중에서만 고를 수 있고 무기한 숨김은 없습니다. 펫을 숨기면 캐릭터와 말풍선이 모두 사라지고 작은 슬라임 화살표만 남습니다. 숨긴 동안 온 메시지는 화살표에 개수로 표시되고, 돌아오면 최신 5개가 함께 뜹니다. 말풍선과 화살표는 흰 슬라임 모양이며 서로 붙어 모이고, 캐릭터와 말풍선은 끌 때 젤리처럼 출렁입니다. 메시지 원문은 콘솔에 출력하지 않습니다.

잠금 화면이나 macOS의 모든 시스템 화면 위에 표시되는 앱은 아닙니다. 전체 화면 앱과 Spaces의 동작은 실제 환경에서 확인하세요. 기본 투명 영역은 아래 앱의 클릭을 통과시킵니다.

## 3. Chrome 확장 프로그램 로드

1. Chrome 주소창에서 `chrome://extensions`를 엽니다.
2. **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누르고 이 프로젝트의 `extension/` 폴더를 선택합니다.
4. 표시된 **32자 확장 프로그램 ID**를 복사합니다. 설정 페이지에도 ID가 보입니다.
5. 이미 열려 있던 Instagram 탭은 새로고침합니다. 확장 프로그램을 다시 로드한 뒤에도 페이지를 새로고침하세요.

Chrome 확장 프로그램의 권한은 `storage`, `nativeMessaging`, 재시도·앱 설정 동기화용 `alarms`, 두 HTTPS Instagram 호스트의 content script 및 재삽입 권한입니다. 모든 사이트·쿠키·방문 기록·화면 녹화 권한을 요구하지 않습니다. Instagram 기능에는 macOS 손쉬운 사용·전체 디스크 접근 권한이 필요하지 않으며, 카카오톡·메시지를 켤 때만 설치된 펫 앱에 별도 권한이 필요합니다. `alarms`는 이미 발견한 이벤트 재전송과 로컬 설정 확인에 사용하며 Instagram을 백그라운드 조회하지 않습니다.

## 4. Native Messaging 호스트 등록

펫을 종료한 뒤, 복사한 실제 ID를 다음 명령의 예시 대신 넣습니다.

```sh
./scripts/install.sh YOUR_32_CHARACTER_EXTENSION_ID
open "$HOME/Applications/InstagramPet.app"
```

`sudo`는 필요 없습니다. 설치 스크립트는 이 사용자 계정 안에 다음을 배치합니다.

```text
~/Applications/InstagramPet.app
~/Library/Application Support/InstagramPet/bin/PetNativeHost
~/Library/Application Support/InstagramPet/config.json
~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.instagrampet.bridge.json
```

호스트 매니페스트는 실제 설치 경로와 **지정한 확장 ID 한 개**만 허용합니다. 수신 이벤트가 새로 수락되면 설치된 펫을 열도록 설정됩니다. 로그인 시 자동 실행이나 상시 백그라운드 수신 서비스를 설치하지 않습니다. 앱을 종료해도 새 이벤트가 도착하면 다시 열릴 수 있으므로 수신을 멈추려면 확장 설정의 **Enable observation**을 끄세요. 자동 실행을 원하지 않으면 `config.json`의 `autoLaunch`를 `false`로 바꿉니다. 호스트는 시작할 때 설정을 읽으므로 `chrome://extensions`에서 확장 프로그램을 다시 로드하고 Instagram 탭도 새로고침한 뒤 연결을 확인합니다.

Chrome의 확장 아이콘 → **Settings & diagnostics**에서 **Check bridge**를 누릅니다. `connected`, `appInstalled: true`를 확인하고 **Send test bubble**을 누릅니다. 테스트용 말풍선이 나타나면 Chrome → Swift 호스트 → 로컬 큐 → 펫 연결을 확인한 것입니다. **이 시험은 Instagram 감지 성공을 의미하지 않습니다.** ACK는 호스트가 큐에 수락했다는 뜻입니다.

설치는 일반 Google Chrome용입니다. Chrome for Testing·Chromium·다른 브라우저는 등록 위치가 다를 수 있습니다. 다른 프로필/폴더에서 확장 ID가 달라졌다면 새 ID로 설치 명령을 다시 실행하세요. 소스를 수정한 뒤에는 다시 빌드하고 설치해야 설치된 복사본도 갱신됩니다.

## 5. 발신자 필터와 실제 DM 시험

1. Chrome에서 Instagram에 로그인하고 `https://www.instagram.com/direct/inbox/`를 엽니다.
2. 펫을 우클릭해 **설정…**을 열고 **인스타그램**의 **상대ID**에 상대방의 **정확한 username**을 입력합니다. 표시 이름은 사용하지 않습니다. `@`는 생략해도 됩니다.
3. 상대방과의 **1:1 대화**를 열어 프로필 계정명을 확인합니다. URL이 `/direct/t/123456789/`라면 앱의 **DM대화창 주소의 번호**에 `123456789`만 입력합니다. 여러 상대는 쉼표로 구분하고 ID와 대화 번호를 **같은 순서·같은 개수**로 적습니다. DOM이 username을 명확히 노출하지 않을 때 사용하는 신원 정보이므로 그룹 대화를 개인 계정에 매핑하지 마세요.
4. 앱에서 저장한 뒤 확장의 다음 설정 동기화가 끝나고 **최소 5초** 기다립니다. 확장 옵션을 열 때도 동기화합니다. 이 구간의 메시지는 초기 기준 상태로 처리될 수 있습니다.
5. 진단에서 `messageRows`, `unknownSender`, `ambiguousText`, `unsupported-dom` 등을 확인합니다. `observing`은 후보 구조를 인식했다는 뜻이며 실수신 보증은 아닙니다.
6. 상대 계정에서 **새 텍스트 DM 한 개**를 보내 봅니다. 본인 답장은 알림으로 표시되지 않아야 합니다. 다른 계정과 기존 내역도 전송되지 않아야 합니다.

확장 옵션의 기존 **Choose the sender**·**Thread bindings** 수동 입력도 유지합니다. 앱에서 Instagram 값을 저장하면 앱 값이 우선하며 옵션에 우선 적용 안내가 표시됩니다. 이때 수동 입력을 저장해도 앱의 상대방 설정을 덮어쓰지 않습니다. 앱에 Instagram 설정이 없는 기존 설치에서는 확장 수동 설정을 그대로 사용합니다. 확장에만 저장된 기존 값은 앱 창에 자동 복사하지 않으므로, 처음 앱에 입력할 때는 확장 옵션에서 상대 username과 1:1 대화 번호를 확인하세요.

기본 파서는 role·메시지 ID·접근성 레이블·프로필 링크·텍스트 구조를 조합합니다. 수신 방향을 확인할 수 없는 화면에서는 설정의 **Advanced: calibrate after Instagram changes its DOM**에 해당 화면에서 확인한 `threadRoot`, `messageRow`, `incomingMessage`, `outgoingMessage`, `messageText` 선택자를 등록할 수 있습니다. 예시 클래스는 실제 Instagram 클래스가 아닙니다. 잘못된 선택자는 본인 메시지를 상대 메시지로 오인할 수 있으므로 [검증 절차](docs/TESTING.md)의 수신·발신·다른 사람 시험을 모두 수행해야 합니다.

inbox에서는 새로 바뀐 **읽지 않은 대화 미리보기**만 보낼 수 있고 말풍선에 **Inbox preview**로 표시합니다. 여러 DM이 한 미리보기로 합쳐지면 중간 메시지를 복구하지 못합니다. 타임스탬프/메시지 ID가 없는 동일 미리보기는 24시간 중복으로 억제될 수 있습니다. ID 없는 대화 본문의 동일 문구 반복도 구분하지 못할 수 있습니다. 페이지를 새로 열거나 긴 중단에서 돌아오면 이전 메시지는 기준 상태로 처리해 재알림을 억제하므로 그 사이 도착한 DM을 놓칠 수 있습니다.

## 6. 앱에서 상대방 설정

펫을 우클릭해 **설정…**을 열면 현재 앱 설정이 채워져 있습니다. 창의 **인스타그램·메세지·카카오톡** 세 구역에 다음 값을 입력하고 저장합니다. **여러 개 등록 가능 · 쉼표(,)로 구분**하며 각 목록은 최대 100개입니다.

| 항목 | 입력 기준 |
| --- | --- |
| 인스타그램 — 상대ID | 상대 계정의 username 목록. 각 ID는 영문·숫자·점·밑줄 1~30자이며 앞의 `@`는 생략 가능 |
| 인스타그램 — DM대화창 주소의 번호 | 1:1 DM 주소 `/direct/t/<번호>/`의 숫자 부분 목록. 각 번호는 ASCII 숫자 1~128자리이며 상대ID와 같은 순서로 입력 |
| 메시지 | 상대 전화번호 또는 이메일 목록. 각 번호·이메일을 따로 정규화하며 국내 `010` 번호는 `+82` 형식과 같은 연락처로 해석 |
| 카카오톡 | **채팅 목록 표시 이름 기준**의 이름 목록. 각 이름 끝의 이모지는 생략할 수 있으며 동명 대화는 구별을 보장하지 않음 |

쉼표 주위의 공백은 제거하고 각 값을 검증합니다. `fixture.one,,fixture.two`처럼 빈 항목이 있거나 마지막에 쉼표가 남으면 오류이며, 한 항목이라도 잘못되면 창에 오류를 표시하고 전체 설정을 저장하지 않습니다. 쉼표는 구분자로만 쓰므로 이름 안의 쉼표를 인용하거나 이스케이프하는 형식은 지원하지 않습니다. Instagram ID·대화 번호의 개수는 같아야 하고 대화 번호는 중복될 수 없습니다. 같은 ID를 서로 다른 대화 번호에 연결할 수 있으며 허용 목록에서는 ID 중복만 제거합니다. 메시지·카카오톡의 중복 항목은 정규화 후 제거합니다.

메시지·카카오톡 입력란 전체를 비우면 해당 소스를 비활성화합니다. Instagram 입력란을 처음 수정하면 앱 설정을 사용하며, ID·대화 번호 목록을 모두 채우거나 모두 비워야 합니다. 두 목록을 지워 저장하면 Instagram 관측 대상도 비활성화합니다. 앱에 Instagram 설정이 없는 기존 설치에서 두 입력란을 건드리지 않고 메시지·카카오톡만 저장하면 기존 확장 수동 설정을 유지합니다. 설정 저장은 macOS 권한을 대신 부여하지 않습니다.

메시지·카카오톡은 저장 후 등록 대상별 reader에 바로 반영합니다. 계속 등록된 상대의 reader와 말풍선·대기 상태는 유지하고 제거된 상대의 말풍선·대기 메시지만 정리합니다. 새로 등록한 상대는 현재 내용을 기준 상태로 잡고 과거 메시지를 재생하지 않으므로 새 수신으로 확인하세요. Instagram은 앱의 로컬 설정을 확장이 Native Messaging으로 읽어 허용 목록·대화 매핑에 반영하는 단방향 동기화입니다. 확장 시작·약 5초 간격 확인·옵션 열기 때 동기화하고, 워커 중단 후에는 1분 간격 알람으로 다시 확인합니다. 확장 수동 입력이 앱 파일로 역전송되지는 않으며 **Enable observation** 일시정지도 그대로 유지하므로 관측할 때는 켜 두세요.

메시지·카카오톡 두 소스는 Chrome 확장 프로그램을 거치지 않고 **실행 중인 펫 앱 내부에서 약 0.5초마다** 관측합니다. 실제 간격에는 OS 스케줄링과 DB·접근성 조회 시간이 더해질 수 있습니다. 앱이 꺼져 있으면 관측하지 않습니다. 시작·권한 복구·DB 교체 또는 카카오톡 목록 재등장 시 기존 내용을 기준 상태로 잡고 과거 메시지를 알림으로 재생하지 않습니다.

설정 파일은 사용자 로컬의 `~/Library/Application Support/InstagramPet/sources.json`에 둡니다. 메뉴의 **Open Local Data Folder**로 폴더를 열 수 있습니다. 앱은 소유자 전용 권한 `600`으로 원자적 교체하며 심볼릭 링크를 거부합니다. 실제 이름·전화번호·이메일을 저장소나 fixture에 넣지 마세요. 아래는 가짜 값만 사용한 복수 등록 예시입니다.

```json
{
  "instagram": { "username": "fixture.one,fixture.two", "threadId": "123456789,987654321" },
  "kakao": { "name": "Fixture Friend,Fixture Other" },
  "messages": { "handle": "one@example.invalid,two@example.invalid" }
}
```

JSON의 필드 구조는 기존과 같으며, 여러 대상은 공백 없는 구분 쉼표와 정규화된 값으로 연결한 문자열에 저장합니다. 이름 자체의 내부 공백은 유지합니다. 파일이 없거나 메시지·카카오톡 항목이 없거나 비어 있으면 해당 로컬 소스는 꺼집니다. 실제 연락처는 사용자 로컬 설정에만 저장합니다. `instagram` 항목이 없는 기존 파일은 확장 수동 설정을 유지하고, `"instagram": {"username": "", "threadId": ""}`는 앱이 관리하는 Instagram을 비활성화합니다. 외부 편집기로 파일을 직접 바꾼 경우에는 펫 앱을 다시 실행하세요. 설치 스크립트는 기존 `sources.json`을 덮어쓰지 않습니다. 실제 수신은 아래 권한 설정 후 새 메시지로 확인해야 합니다.

### 카카오톡

시스템 설정 → 개인정보 보호 및 보안 → **손쉬운 사용**에서 설치된 `InstagramPet.app`을 추가하고 켭니다. 개별 알림 경로에는 같은 앱의 **전체 디스크 접근** 권한도 필요합니다. 기존에 Messages용으로 허용했다면 같은 권한을 사용하며, 새 연락처 설정이나 별도 데몬을 추가하지 않습니다. 권한을 바꾼 뒤 펫 앱을 다시 실행하세요.

카카오톡의 macOS **알림 허용**, 배너 또는 알림 표시, **내용 미리보기**를 켜서 시험하세요. 이 경로는 `~/Library/Group Containers/group.com.apple.usernoted/db2/db`를 SQLite 읽기 전용으로 확인합니다. 앱 번들 `com.kakao.KakaoTalkMac` 전체를 대소문자 구분 없이 비교하고, 알림 제목이 로컬 `kakao.name`과 정확히 일치하거나 그 이름 뒤에 이모지만 붙은 경우에만 본문을 전달합니다. 비어 있지 않은 부제목은 그룹 대화 가능성이 있어 거부합니다. 일반 텍스트가 더 붙은 이름·다른 앱·다른 연락처·설정한 이름과 일치하지 않는 일반적인 앱 제목은 전달하지 않습니다. 표시 이름은 계정 신원 확인 수단이 아니므로 동명 대화를 완전히 구별할 수는 없습니다.

알림 DB의 첫 성공한 조회와 권한 복구·DB 교체는 기준 상태로 삼고 이전 알림을 재생하지 않습니다. 이후 개별 알림 레코드와 마지막 수정 상태를 구분하므로 서로 다른 알림의 본문이 같아도 각각 전달합니다. **OS가 레코드를 삭제했거나 같은 레코드를 여러 번 덮어쓴 경우, 관측 전에 사라진 중간 내용은 복구할 수 없습니다.** 알림이 생성되지 않거나 미리보기가 숨겨지거나 지원하지 않는 형식이면 개별 본문을 얻지 못할 수 있습니다. 이 DB는 macOS 내부 형식이므로 OS 업데이트에 따라 호환 확인이 필요합니다.

**목록 AX 경로는 읽음 판정과 알림이 없는 경우의 대체 수신 경로로 유지합니다.** 카카오톡을 실행하고 최소화하지 않은 채팅 목록에서 등록한 대상 행들이 보이도록 두세요. 수신 관측을 위해 앱을 활성화하거나 대화를 선택하거나 스크롤하지 않습니다. 한 등록 이름과 일치하는 행이 여러 개이거나 구조가 불명확하면 그 대상은 목록에서 감지하지 않습니다. 읽지 않은 수가 0보다 크고 미리보기·절대 시각이 바뀌면 새 미리보기로 처리하며, 동일 문구·동일 시각도 안정된 기준보다 높은 배지가 정상 스냅샷 두 번에서 확인되면 반복 수신의 증거로 사용합니다. 단발 숫자 변화나 날짜 표시의 자정 변경은 새 메시지로 만들지 않습니다. 배지가 사라진 완전한 행을 연속 두 번 확인하면 해당 대화의 말풍선만 지웁니다. 알림센터에서 알림이 삭제됐다는 사실은 읽음 증거로 사용하지 않습니다.

개별 알림을 우선 전달하고, 대응하는 알림이 없으면 잠시 기다린 뒤 AX 미리보기를 전달합니다. 알림·목록 양쪽에서 본 같은 메시지는 시간과 본문으로 대응시켜 중복을 억제합니다. 확실히 대응시키지 못한 경우에는 실제 새 수신을 버리지 않도록 일부 중복이 남을 수 있습니다. AX 미리보기는 잘릴 수 있고, 한 번의 관측 사이에 여러 메시지가 오면 마지막 것만 보입니다. 같은 문구·시각·배지의 반복은 AX만으로 구별하지 못합니다. 목록 창이 없거나 대상 행이 화면 밖이면 AX 수신·읽음 판단은 보류하지만, 지원하는 개별 알림은 별도로 관측할 수 있습니다.

메뉴의 **KakaoTalk** 상태 줄에서 `알림 + 목록`, 개별 알림용 전체 디스크 접근 필요, 읽음 연동용 목록 창 확인 등의 상태를 확인합니다. `관측 중`은 해당 경로를 읽었다는 뜻이며 새 메시지 전달 성공을 보증하지 않습니다. 실제 새 메시지 수신·읽음 전환은 별도 시험이 필요합니다.

### Apple 메시지(iMessage/SMS)

`messages.handle`을 채운 뒤 시스템 설정 → 개인정보 보호 및 보안 → **전체 디스크 접근**에서 설치된 `InstagramPet.app`을 추가하고 켜 주세요. 이후 펫 앱을 다시 실행합니다. 연락처가 비어 있으면 DB를 열거나 이 권한을 요청하지 않습니다. 필요한 권한이 없을 때 앱은 실행당 한 번 안내하고 메뉴의 **Messages** 상태 줄에 표시합니다.

앱은 `~/Library/Messages/chat.db`를 SQLite **읽기 전용**으로 열어 등록한 각 연락처의 새 1:1 수신 행만 읽습니다. 본인 발신·등록하지 않은 연락처·그룹 대화는 제외하며, 처음 성공한 조회를 기준으로 과거 이력을 재생하지 않습니다. 일반 텍스트와 지원하는 `attributedBody`를 읽고, 첨부는 파일을 열지 않고 MIME 종류에 따라 `(이미지)`·`(동영상)`·`(첨부)`로 표시합니다. 지원하지 않는 본문 형식이나 DB 스키마에서는 누락될 수 있습니다. Mac에 동기화되지 않은 iPhone 메시지는 읽을 수 없습니다.

관측한 메시지가 원본 DB에서 읽음으로 바뀌면 해당 메시지 대화의 말풍선만 제거합니다. 읽지 않은 다른 관측 메시지가 남아 있으면 이를 지우지 않도록 읽음 반영을 보류할 수 있습니다. 실제 전체 디스크 접근 허용, 연락처 대화 열기, 수신·읽음은 사용자 시험이 필요합니다.

### 클릭과 읽음 확인

| 말풍선 | 테두리 | 클릭 시 동작 | 원본 앱에서 읽을 때 |
| --- | --- | --- | --- |
| Instagram | 분홍·주황·보라 그라데이션 | Chrome에서 해당 DM 열기 | 확장의 기존 대화 읽음 동기화 |
| KakaoTalk | 노랑 | 카카오톡 활성화, 해당 대화 자동 선택은 하지 않음 | 지원하는 목록에서 배지 소멸 확인 |
| Messages | 초록 | 말풍선의 대화와 일치하는 등록 연락처의 `sms:` 링크를 메시지 앱으로 열기 | 관측 행의 `is_read` 확인 |

클릭에 성공하면 **그 소스의 그 대화**에 속한 기존 말풍선만 지웁니다. 같은 소스의 다른 등록 상대, 다른 소스의 대화와 이후에 도착한 메시지는 남습니다. 카카오톡 앱 활성화만으로 카카오톡 자체의 읽음 배지가 사라지는 것은 아닙니다. 세 소스의 순서·시간·배치·숨김·12시간 만료 규칙은 함께 적용됩니다.

처음 설정한 뒤 새 메시지를 받아 해당 색·내용을 확인하고, 다른 소스의 말풍선이 함께 있는 상태에서 한 대화만 읽어 나머지가 유지되는지 시험하세요. 실제 이름·본문을 시험 보고서에 붙이지 마세요.

## 7. 테스트

프로젝트 루트에서:

```sh
cd extension
npm ci
npm test
cd ../macos
swift run PetCoreChecks
swift run PetSourcesChecks
cd ..
./scripts/build-app.sh
./scripts/test-native.py
./scripts/test-install.py
./scripts/test-app.py
```

Swift 검사는 전체 Xcode의 XCTest가 없는 Command Line Tools 환경에서도 실행되도록 실행형 검사 도구로 만들었습니다. 확장 프로그램은 fixture 파싱과 상태 전이/필터/워커 큐를, `PetCoreChecks`는 소스별 모델·읽음·설정·입력 검증·디스크 큐·프레이밍을, `PetSourcesChecks`는 합성 SQLite DB와 접근성 트리로 시작 기준 상태·수신 필터·재시도·읽음을 확인합니다. 실제 메시지 DB나 카카오톡 접근성 권한은 자동 테스트에 사용하지 않습니다. Python 통합 검사는 **실제 Swift 호스트 실행 파일**과 혼합 소스 말풍선의 읽음 격리를 검증합니다. 설치 테스트는 임시 폴더에서 수행하며 사용자 Chrome 설정을 바꾸지 않습니다. 앱 smoke test는 로그인된 macOS 데스크톱 세션에서 창을 표시하지 않고 실제 큐 수신→말풍선 생성→큐 소비를 확인합니다. `--render-scenarios <출력 폴더>`에는 세 소스가 섞인 말풍선과 카카오톡 읽음 후 화면도 포함됩니다.

검증 당시 결과와 한계는 [VALIDATION.md](docs/VALIDATION.md), 실제 계정 확인 목록은 [TESTING.md](docs/TESTING.md)에 있습니다.

## 문제 해결

| 증상 | 확인할 곳 |
| --- | --- |
| Native messaging host not found | 실제 확장 ID로 `install.sh` 실행 여부, 일반 Chrome의 등록 경로, `path`의 실행 파일 존재 여부 |
| Access forbidden / caller check failed | 확장 ID가 호스트 allowed_origins 및 config.json과 모두 같은지 |
| connected인데 말풍선 없음 | appInstalled, 설치된 앱 실행, 숨김/일시정지 상태, native queue depth 확인 |
| heartbeat 없음 | Instagram 탭 새로고침, 로그인된 DM 페이지인지, Chrome의 사이트 접근 허용 여부 |
| unsupported-dom / unknownSender | 정확한 허용 목록, 검증된 1:1 binding, DOM 선택자 조정 및 fixture 회귀 시험 |
| 기존 메시지가 안 옴 | 최초/재개 기준 상태 처리가 정상일 수 있음. 기다린 뒤 새 DM으로 시험 |
| 같은 메시지 반복 / 누락 | 잘못된 선택자, DOM 노드 재활용, preview 집계, ID 부재와 백그라운드 중단 여부 확인 |
| KakaoTalk / Messages 꺼짐 | 펫 우클릭 **설정…**에서 해당 값을 채워 저장하고 권한·상태 확인 |
| 앱에서 Instagram을 바꿨는데 확장 값이 다름 | 앱에서 입력·저장했는지, Native Messaging 연결, 확장 옵션의 앱 우선 적용 안내와 동기화 상태 확인 |
| KakaoTalk 대기 / 목록 구조 인식 불가 | 카카오톡 실행·목록 창·대상 행 표시·지원 구조 여부 확인 |
| KakaoTalk 목록만 관측 / 개별 알림 없음 | 펫의 전체 디스크 접근과 카카오톡 알림 허용·내용 미리보기 확인. OS 알림이 없으면 AX 경로로만 감지 |
| 손쉬운 사용 / 전체 디스크 접근 필요 | 시스템 설정에서 설치된 펫 앱의 해당 권한을 켜고 재실행 |
| Messages DB/스키마 확인 필요 | Mac의 메시지 동기화·DB 존재·지원 스키마 확인. 실제 DB를 수정하지 말 것 |

설정에서 **Log metadata**를 켜면 Instagram 탭 개발자 도구 콘솔에 상태와 개수만 기록합니다. 서비스 워커 오류는 `chrome://extensions`의 **service worker** 검사에서 확인합니다. 메시지 본문·계정명·전체 DOM·쿠키·HAR를 보고서에 붙이지 마세요. Chrome의 Native Messaging 로그와 일반 로그가 프로토콜 stdout에 섞이면 연결이 깨집니다.

로컬 큐 검사와 삭제:

```sh
"$HOME/Library/Application Support/InstagramPet/bin/PetNativeHost" --status
"$HOME/Library/Application Support/InstagramPet/bin/PetNativeHost" --clear
```

확장 대기 큐는 최대 100개/5분, Swift 대기 큐는 최대 200개/24시간입니다. 만료 파일의 실제 삭제는 다음 큐 접근 때 이뤄집니다. 펫은 표시한 이벤트 파일을 지우고, 중복 확인용 내용 없는 기록만 제한적으로 보관합니다. 자세한 데이터 위치와 한계는 [SECURITY.md](docs/SECURITY.md)를 참고하세요.

## 제거

펫을 종료한 뒤 실행합니다.

```sh
./scripts/uninstall.sh --delete-data
```

앱·호스트 등록·프로젝트 전용 로컬 큐와 설정을 제거합니다. 로컬 데이터를 남기려면 `--delete-data`를 생략합니다. Chrome의 `chrome://extensions`에서 확장 프로그램도 제거하세요. 앱의 위치 설정까지 초기화하려면 `defaults delete com.instagrampet.app`을 사용할 수 있습니다.

## 구조

```text
extension/                  MV3, DOM adapter/tracker, 설정, 전달 큐, fixture 테스트
macos/Package.swift         Swift Package (PetCore / PetSources / 호스트 / 앱 / 실행형 검사)
macos/Sources/PetCore/      이벤트 검증, 원자적 private 큐, 중복 수락 기록, framing
macos/Sources/PetSources/   Messages·알림센터 읽기 전용 SQLite, KakaoTalk AX 목록·읽음 관측
macos/Sources/PetNativeHost/ Chrome stdio 호스트 + 명시적인 로컬 demo/status/clear 명령
macos/Sources/InstagramPet/ AppKit 펫과 말풍선, 메뉴, 큐 소비
scripts/                    빌드·설치·제거·네이티브/설치 통합 테스트
dist/                       빌드한 앱과 Swift 호스트 (이 빌드는 arm64)
docs/                       프로토콜, 테스트 결과, DOM 변경 대응, 개인정보 처리
```

이 통신은 Chrome이 호스트 프로세스를 시작해 표준 입력/출력으로 교환하는 방식입니다. 로컬 HTTP 서버나 포트를 열지 않습니다. 등록 경로와 프레이밍은 [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging), 감지 가능한 페이지 범위는 [content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), 재시작 내구성은 [service worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)을 기준으로 구현했습니다.
